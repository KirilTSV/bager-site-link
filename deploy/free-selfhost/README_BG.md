# BAGER SITE LINK — самостоятелен хостинг без задължителен абонамент

## Статус
Това е **подготвен deployment комплект**, не доказателство за успешно внедряване. Не гарантира вечна безплатна работа, непрекъсваемост, нулеви разходи за интернет/електричество или достъпни безплатни облачни ресурси. Не заменя полевите, PostgreSQL и браузърните проверки.

## Предпоставки
- Собствен Linux сървър или безплатна VM, на която Docker Engine + Compose могат да се използват съобразно условията на доставчика.
- Публичен IPv4 адрес, DNS име, сочещо към него, и достъпни TCP 80/443 и UDP 443 (за HTTPS). Може да използвате безплатен DNS поддомейн при съответните условия.
- Защитен SSH достъп, обновявана ОС, firewall, свободен диск и план за наблюдение.
- Не използвайте Render продукционната база или нейните тайни в този комплект.

## Инсталиране
1. Инсталирайте Docker Engine и Docker Compose plugin на сървъра.
2. Клонирайте проверения GitHub revision на BAGER SITE LINK (не използвайте непроверен staging commit за реални данни).
3. `cd deploy/free-selfhost`; `cp .env.example .env`; `chmod 600 .env`.
4. Задайте `SITE_DOMAIN`, отделни силни пароли `POSTGRES_PASSWORD` и `BAGER_ADMIN_PASSWORD`. Използвайте дълги случайни букви и цифри за PostgreSQL паролата, тъй като тя се вгражда в URL.
5. `docker compose config -q` (проверка на конфигурацията).
6. `docker compose up -d --build`.
7. Проверете `docker compose ps`, `docker compose logs --tail=100 app proxy db`, `https://ВАШИЯ-ДОМЕЙН/health`.
8. Проверете вход, роли, смени, GPS, курсове и възстановяване на резервно копие **с тестови данни** преди реална употреба.

## Архитектура
Caddy (автоматичен HTTPS) -> FastAPI (вътрешна мрежа) -> PostgreSQL 17 (вътрешна мрежа). PostgreSQL портът не се публикува в интернет. Данните са в Docker named volume `postgres_data`; `docker compose down -v` ги **изтрива**. Никога не изпълнявайте `down -v` за работеща инсталация.

## Архивиране и възстановяване
- `bash backup.sh` създава PostgreSQL custom-format dump в `backups/` с ограничени права.
- Създайте отделно **криптирано копие извън сървъра**; локален backup не предпазва от загуба на VM/диск.
- Проверявайте периодично restore на отделна тестова инсталация. Възстановяване в текущата база: `bash restore.sh backups/ИМЕ.dump` — разрушителна операция с изрично потвърждение.
- Планирайте `backup.sh` чрез systemd timer/cron и следете за неуспехи. Не изтривайте стари архиви, докато нямате проверени копия извън машината.

## Ограничения и сигурност
- Безплатните облачни доставчици не гарантират капацитет или вечен безплатен план.
- Текущият код извършва `Base.metadata.create_all` при import и `seed()` при стартиране; преди продукционна миграция е необходим преглед на миграции, първоначални акаунти и права.
- Не включвайте истински данни, докато не бъдат проверени CSRF защита, origin/proxy конфигурация, HTTPS, backup/restore, rate limiting, тайни, журнал и GDPR.
- При проблем с хоста, DNS или доставчика услугата може да прекъсне. Поддържайте възстановим архив и документ за миграция.
- Това не мигрира съществуващите Render данни автоматично. Миграцията изисква отделно одобрение и контролирана процедура.
