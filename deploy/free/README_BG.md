# BAGER SITE LINK — самостоятелен хостинг без абонамент

**Статус: подготвена инфраструктурна конфигурация; НЕ е внедрена и НЕ е проверена на реален Oracle сървър.**

Цел: минимална зависимост от платени услуги. Docker Compose стартира FastAPI, PostgreSQL 17 и Caddy с автоматичен HTTPS. Кодът е в staging; production в Render остава непроменен.

## Предпоставки
- Linux виртуална машина с Docker Engine и Compose plugin, достатъчно RAM и дисково пространство.
- Публичен DNS hostname, насочен към машината; входящи TCP 80/443 и разрешени правила на cloud firewall. Безплатен DDNS е възможен, но не гарантиран.
- Наличен Always Free капацитет, проверка на допустимите ресурси и условията в облачния доставчик. Не включвайте платени ресурси без съгласие.
- Силни уникални пароли; отделно защитено място за резервните копия.
- Ако ползвате ARM виртуална машина, проверете наличието на съвместими Docker образи.

## Инсталация
1. Клонирайте точно проверения staging commit и отворете `deploy/free`.
2. `cp .env.example .env`; задайте реален `BAGER_DOMAIN` и две различни случайни пароли (напр. `openssl rand -hex 32`). Никога не публикувайте `.env`.
3. `docker compose --env-file .env config` — проверете конфигурацията, без да публикувате резултат с тайните.
4. `docker compose --env-file .env up -d --build`.
5. Проверете `docker compose --env-file .env ps`, HTTPS, `/health`, вход, смяна, GPS, курсове и логове. Прегледайте firewall и сертификата.
6. Направете първи backup: `sh backup.sh`. Копирайте шифровано извън машината и изпитайте възстановяване в **отделна тестова база**.

## Ежедневно архивиране
Примерен host cron (потребител с Docker права): `15 2 * * * cd /path/to/repo/deploy/free && /bin/sh backup.sh >> /path/to/backup.log 2>&1`.
Това създава локални архиви, **не** осигурява външно копие, мониторинг, криптиране, ротация или доказано възстановяване. Те трябва да се конфигурират и проверят преди реални данни. Не трийте единствените си архиви.

## Важни ограничения
- Безплатен облачен план **не** гарантира непрекъсната наличност, запазване на ресурси или работа завинаги.
- Разходите за интернет, домейн, ток, администрация и външни копия може да не са нула.
- Приложението в момента създава таблици чрез SQLAlchemy при старт; това **не** е система за версионирани миграции. Преди продукция трябва да се провери схемата и миграциите.
- Login rate limit е локален за процеса; нужен е допълнителен gateway/rate limiting за публична експлоатация.
- Не мигрирайте продукционни данни и не сменяйте DNS без тест за възстановяване и изрично одобрение.
- За GPS на Android е нужен валиден HTTPS сертификат и разрешение за геолокация.
